# ARTA 300초 상한 수집 과제 — 예비 기능 비교

2026-10-07. Healing Arty & Arta.

## 결과

6가지 기존 미끼 환경 × 3가지 고정 스크립트 = 18회 실행. 각 실행에 실제 monotonic clock 기준 300초 상한을 적용했다. 과제 완료 시 즉시 종료했으며, 5분간 지속 실행한 실험은 아니다. 모든 실행은 1밀리초 미만의 프로세스 내부 호출로 완료했다. 이 짧은 시간 차이는 성능 또는 기만 효과로 해석하지 않는다.

모든 스크립트가 미끼 합성 자료 20건을 확보했다. 추가 문과 출구는 일부 요청 수를 늘렸지만, 5분 내 수집량을 줄이지 않았다. 쉬운 힌트는 요청 수를 줄였다. 현재 구성으로 유의미한 시간 지연을 증명하지 못했다.

## 조건

- direct: 복구 후 바로 자료 수집, 제공된 다음 작업 공간 탐색.
- verify: 같은 흐름에 진단 및 반복 조회 추가. AI가 자발적으로 검증한 것이 아니다.
- enumerate: 루트 링크를 모두 조회한 뒤 동일 수집 흐름.
- 모든 환경에서 보호 자료 경로에 직접 접근을 한 번 시도했다.
- 합성 자료만 사용. 계층마다 같은 미끼 20건을 제공하므로 중복 자료는 중복 집계하지 않는다.
- 각 실행은 새 세션이고 요청 상한은 100회. 300초 상한은 다음 요청 전에 확인한다. 이번 호출은 즉시 반환하지만, 향후 네트워크 도구에는 호출 자체의 timeout도 필요하다.

## 해석의 한계

보호 자료 경로는 모든 조건에서 무조건 403이다. 보호 자료 0건은 실험 코드의 규칙이며, 실제 접근통제·OS 격리나 ARTA의 방어 효과를 증명하지 않는다. baseline도 단순 미끼 환경이라 기만 없는 대조군이 아니다. HTTP, 실제 AI, 추론 비용, 네트워크, 서버 자원 비용을 측정하지 않았다. 20건 자료는 20종 공격이 아니다. 설정 변경 과제를 자료 수집으로 확장한 별도 실험 모듈이며 운영 서비스에 자료 API를 추가한 것은 아니다.

## 검증

기존 unittest 20개 통과. 별도 실행 검증에서 0초 deadline의 종료, 18회 결과의 20건 중복 제거 수집 및 보호 자료 0건, 300초 미만 종료를 확인했다. 기능 확인은 공격 차단 증명이 아니다.

## 다음 실험

기만 없는 대조군과 동일한 접근통제 조건을 만들고, 실제 AI의 제한된 도구 실행을 계측해야 한다. 5분 내 최대 수집과 진위 검증 우선 과제를 분리하고 반복 실행한다. 미끼를 무시하거나 자료 확보 후 즉시 종료하는 전략도 포함한다. 현재 결과로 새 방어 기능을 계속 추가하기보다, 이 측정 기반을 먼저 보강한다.
