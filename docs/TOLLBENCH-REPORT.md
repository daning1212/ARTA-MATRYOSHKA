# Healing Arty & Arta 공동개발 — 아이리스 계산 통행료 실험 보고서

2026-10-07. 별도 localhost HTTP 마이크로벤치마크이며 기존 미끼 세계에는 통합하지 않았다.

## 조건과 결과

계산 통행료 없음(bits=0)과 SHA-256 14-bit 퍼즐을 비교했다.
각 실행 2초, 클라이언트 스레드 1개/2개, 조건별 3회 반복으로 총 12회 실시했다.
순서 편향을 줄이기 위해 반복마다 조건 실행 순서를 번갈아 바꿨다.
클라이언트와 서버는 별도 프로세스지만 동일 머신의 CPU를 공유한다.

| 클라이언트 수 | 퍼즐 비트 | 평균 반복 조회 건수 | 클라이언트 CPU초 | 서버 CPU초 |
|---|---:|---:|---:|---:|
| 1 | 0 | 9934.7 | 1.289 | 1.139 |
| 1 | 14 | 167.3 | 1.940 | 0.080 |
| 2 | 0 | 13126.0 | 2.140 | 1.471 |
| 2 | 14 | 163.7 | 2.000 | 0.072 |

이 값은 같은 가짜 자료를 반복 조회한 처리량이다. 1/2개 클라이언트가 각각 같은 자료를
재조회한다. 고유 자료의 탈취량 또는 개인정보 유출 방지 성과가 아니다.
서버의 초당 처리량 감소와 클라이언트 계산 증가를 이 조건에서 관측했다.
AI가 속거나 더 오래 생각한다는 증거가 아니다.

## 구현한 기능

- 외부 주소를 인자로 받지 않는 localhost 전용 별도 실험 서버.
- 합성 자료 네 종류만 제공. 실제 파일/계정/서버와 연결하지 않음.
- 퍼즐에 조회할 자료 ID를 연결하고 만료 10초·일회성 적용.
- 미완료 퍼즐 최대 128개, 입력 본문 1 KiB, 난이도 최대 18비트.
- 성공 검증은 SHA-256 한 번. 생성/검증/HTTP 등 서버 전체 CPU를 별도로 측정.
- 재사용·잘못된 자료 연결·만료·잘못된 입력 거부 테스트.

퍼즐은 bearer 방식이며 사용자 인증 또는 기기 연결은 아니다. 세션 간 전달을 막지 않는다.
현재 실험 서버는 기본 애플리케이션과 분리되어 있고 실제 서버 방어에는 적용하지 않았다.

## 안전 검증과 한계

새 network namespace 생성은 실행 환경 권한 때문에 실패했다.
Docker도 이 환경에 없어 OS/네트워크 격리 검증을 완료하지 못했다.
별도 프로세스는 샌드박스가 아니다. 따라서 신뢰할 수 없는 공격 코드나 실제 AI 도구를
실행하지 않고 우리가 작성한 제한된 합성 조회 스크립트만 실행했다.

실제 300초 실험은 하지 않았다. 2초의 작은 난이도 기능/처리량 비교를 먼저 수행했다.
2개 스레드는 Python GIL과 동일 CPU 영향을 받으므로 GPU·다중 프로세스·분산 병렬화
저항성을 증명하지 않는다. 일반 해시 PoW는 병렬화 가능하다.
별도 검증 조회 전략·실제 AI·실제 보호 자료 비교도 미실시다.
서버 단일 처리와 클라이언트 구현 차이가 결과에 영향을 준다.
OS 전체 자원 상한/메모리 비용/전력 비용은 측정하지 않았다.
퍼즐을 건너뛰고 다른 취약점을 노리는 공격은 막았다고 주장할 수 없다.

## 실행과 다음 단계

```bash
python -m unittest discover -s tests -v
python -m arta.tollbench --seconds 2 --repeats 3
```

CLI는 실행당 최대 300초를 허용하지만 총 실행은 클라이언트 2조건 × 통행료 2조건 × 반복 수다.
기본은 12회 × 2초다. `--seconds 300`을 지정하면 전체가 5분이 아니라 약 1시간일 수 있다.
결과 JSON은 stdout으로 출력한다. 기존 보고서와 원본 결과를 덮어쓰지 않는다.

다음 순서는 검증된 외부 격리 환경 확보 → 300초 반복 측정 → 다중 프로세스·조기 포기·검증 전략 비교
→ 실제 AI 계측이다. 연구 목적에 맞는 합성 자료의 고유 수집량도 따로 측정해야 한다.
