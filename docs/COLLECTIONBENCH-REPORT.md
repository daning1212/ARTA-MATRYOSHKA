# 고유 합성 자료 수집 실험 보고서

2026-10-07. Healing Arty & Arta 공동개발.

## 결론

SHA-256 퍼즐이 이 구현의 합성 자료 수집량을 줄였지만 방어 효과를 입증한 결과는 아니다.
14비트 조건에서 프로세스 1개 → 2개 → 4개로 늘리자 평균 수집량은
275.4 → 572.4 → 800.0건으로 증가했다. 일반 해시 PoW는 병렬화 가능하며
기존 스레드 결과로 병렬 계산 저항성을 주장할 수 없음을 확인했다.

**후속 재현 주석:** 별도 [3조건 대조 실험](CONTROLBENCH-REPORT.md)에서는
2프로세스 PoW가 329.8 ± 168.0건(97–540)으로, 이 보고서의 572.4 ± 34.4건을 재현하지 못했다.
두 실험 모두 1→4프로세스에서는 수집량이 증가했지만, 증가 크기는 불안정하고
1→2→4의 안정적인 확장성을 입증하지 않는다. 두 원본 결과를 합쳐 평균내거나
“병렬화로 성능을 되찾는다”는 일반적 결론으로 사용하지 않는다.

## 방법

외부 패키지 없이 Python 3.12.14, Linux, 표시된 논리 CPU 9개인 환경에서 실행했다.
같은 호스트의 localhost 단일 동기식 HTTP 서버와 독립 클라이언트 프로세스를 사용했다.
논리 CPU 표시는 실제 전용 코어 수·컨테이너 CPU 할당·다른 작업의 부재를 보장하지 않는다.
일부 측정 구간에 기능 테스트가 병행되었다. 전용 머신의 통제된 성능 측정이 아니므로
수치를 예비 관측으로만 사용한다. 장기 측정·추가 장비에서 재현이 필요하다.

- 자료 100,000개. 각 자료는 ID만 다르고 동일한 크기의 합성 payload를 가진다.
- 클라이언트별로 ID를 분할하여 동일 자료 재조회 없이 순서대로 수집한다.
- 프로세스 1·2·4개, 퍼즐 없음·14비트, 각 5회: 총 30회.
- 각 실행 공통 시간 예산 5초. 모든 클라이언트가 준비된 뒤 시작한다.
- 총 측정 구간 약 150.04초. 프로세스 준비·종료 시간은 별도다.
- 반복마다 프로세스 수 순서를 회전하고 기준선·통행료 순서를 교대했다.
- HTTP 요청 또는 증명 실패는 오류로 기록하고 다음 ID로 진행하는 고정 전략이다.
- CPU초는 클라이언트 프로세스별 사용량을 합산한다. 서버 CPU는 준비 후 종료까지다.

## 결과

수집량은 클라이언트가 성공 응답으로 확인한 고유 건수다. 평균 ± 표본 표준편차.

|---:|---:|---:|---:|---:|---:|---:|
| 1 | 0 | 12798.0 ± 2556.4 | 10066–16731 | 2.757 | 2.483 | 1 |
| 1 | 14 | 275.4 ± 38.7 | 218–324 | 4.812 | 0.213 | 0 |
| 2 | 0 | 23572.0 ± 5096.9 | 16220–30315 | 4.730 | 4.078 | 0 |
| 2 | 14 | 572.4 ± 34.4 | 535–609 | 9.659 | 0.369 | 0 |
| 4 | 0 | 21728.6 ± 3906.4 | 17489–26447 | 6.087 | 4.842 | 0 |
| 4 | 14 | 800.0 ± 163.3 | 511–903 | 19.115 | 0.624 | 0 |

모든 실행에서 자료는 소진되지 않았다. 1프로세스·통행료 없음 조건의 1회에서
시간 경계에 클라이언트 오류 1건이 발생했고 서버 제공 건수가 클라이언트 확인 건수보다
1건 많았다. 서버가 기록했다고 클라이언트가 확보했다고 간주하지 않는다.
원본에 양쪽 건수와 일치 여부를 보존했으며 오류를 제외하거나 성공 건수에 더하지 않았다.

### 14비트 난이도의 의미

해시 출력이 균일하고 서로 다른 nonce 시도를 독립으로 근사하면 성공 확률은 2^-14이고,
성공 해시를 포함한 평균 시도 수는 **2^14 = 16,384회**입니다. 고정된 횟수나 시간 보장이 아니며 실제 탐색량은 달라집니다.
이는 작은 작업량으로, 최적화된 네이티브 코드·GPU에도 유의미한 장벽이 된다고 주장할 수 없습니다.
GPU 비용은 측정하지 않았으므로 “무료”라는 수치적 결론도 내리지 않습니다.
관측 결과는 **이 고정 Python 클라이언트 구현이 추가 솔버 작업 때문에 느려진다**는 범위에서 해석합니다.
향후에는 같은 왕복 대조군·시간·자원 예산으로 비트 수를 바꾸어 고유 수집량과 양측 비용 곡선을 비교할 수 있습니다.
난이도별 곡선은 아직 측정하지 않았습니다. 고유 자료 수집 CLI의 `arta.collectionbench --bits`는 현재 1..18비트를 지원합니다.

## 해석의 한계

- 기준선은 요청 1개, 통행료는 challenge와 record 요청 2개다. 추가 왕복 비용도 포함된다.
  같은 요청 수의 0비트 퍼즐 대조군은 아직 없으므로 차이 전체를 해시 계산에 돌리지 않는다.
- 5초 × 5회는 기존보다 확장된 예비 측정이다. 장기 지속성과 운영 효과는 검증하지 않았다.
- Python 루프와 매번 deadline을 확인하는 비용을 포함한다. 최적화된 네이티브/GPU 성능의 추정값이 아니다.
- 단일 서버 처리 한계와 동일 호스트의 CPU 경쟁이 있다. 네트워크 지연을 분리하지 않았다.
- 서버 CPU 감소는 요청 감소와 함께 관측된 현상이다. 공격 중 가용성·방어 비용 증명이 아니다.
- 공격자가 다른 경로를 이용하거나 퍼즐을 우회하는 경우는 비교하지 않았다.
- 정상 사용자 부담·실제 AI 탐색·GPU·분산 계산·메모리·전력·OS 격리는 검증하지 않았다.
- 미끼 앱에 통합하지 않았고 실제 파일·개인정보·보호 자산을 사용하지 않았다.

## 미검증 항목과 이유

여기서 **미검증**은 효과가 없다는 결론도, 앞으로 검증할 수 없다는 뜻도 아닙니다.
현재 확보한 구현·실험·측정 결과로 해당 주장을 입증하지 못했다는 뜻입니다.
기능 테스트 통과와 실제 보안 효과 검증은 구분합니다.

| 미검증 항목 | 아직 검증하지 못한 이유 | 검증에 필요한 것 |
|---|---|---|
| 실제 AI의 미끼 탐색·기만·포기 효과 | 지금까지 직접 실행한 것은 고정 스크립트입니다. 실제 AI의 행동과 비교군을 반복 측정한 기록이 없고, 신뢰할 수 없는 도구를 실행할 격리 경계도 검증되지 않았습니다. | 검증된 격리 환경에서 미끼 유무·모델·전략별 반복 실험과 탐색 경로·검증 행동·수집량·포기율 계측 |
| 강력한 OS·네트워크 격리 | 기본 앱은 같은 OS 계정의 별도 프로세스입니다. 호스트 파일·토큰 접근과 외부 통신을 막는 OS 정책이 앱에 구현·검증되지 않았습니다. 기존 실험에서 network namespace 생성은 권한 문제로 실패했고 Docker도 없어 해당 경로를 검증하지 못했습니다. | 권한 분리·파일 접근 제한·네트워크 정책 구성 후 금지된 파일 접근과 외부 통신이 실제로 차단되는지 시험 |
| GPU·분산 계산에 대한 통행료 저항성 | 실행한 비교는 같은 호스트의 CPU 프로세스 1·2·4개뿐입니다. GPU 또는 여러 호스트의 실행 결과가 없으며, 일반 해시 PoW는 병렬화 가능합니다. | GPU·여러 호스트·최적화된 구현을 사용한 동일 시간·비용 예산 비교 |
| 장기 성능·서로 다른 환경에서의 재현성 | 새 측정은 조건별 5초 × 5회입니다. 일부 구간에 기능 테스트가 병행되었고 전용 자원·장기 지속 부하·다른 장비에서 재현하지 않았습니다. | 통제된 환경의 장기 반복 측정과 장비·자원 할당·부하 조건 공개 |
| 감소량 중 순수 해시 계산의 기여 | 기준선은 HTTP 요청 1개, 통행료는 2개여서 왕복·Python 루프·서버 처리 비용이 섞입니다. 같은 왕복 수의 무계산 대조군을 아직 실행하지 않았습니다. | 동일 요청 수의 무계산 대조군과 계산·왕복·서버 비용 분리 측정 |
| 운영 가용성·정상 사용자 부담·실제 자료 보호 | 합성 자료를 쓰는 localhost 예비 실험이며 통행료는 본 앱·운영 서비스와 미통합입니다. 실제 인증·보호 자산 경계, 느린 연결·폭주, 정상 사용자 흐름을 검증하지 않았습니다. | 합성 보호 자산을 둔 격리된 서비스 비교와 정상 요청 지연·오류·공격 중 가용성·우회 경로 시험 |
| 기록의 완전성·침해 후 신뢰성 | UDP는 전달 보장이 없고 기록 해시는 전체 재작성·삭제를 막지 못합니다. 같은 계정이 장악된 뒤에도 기록이 안전하다는 검증은 없습니다. | 권한이 분리된 수집·보관 경계와 이벤트 유실·위조·삭제·변조 시험 |

격리 설계·대조군 구현·장기 실험 코드를 작성하는 일은 가능합니다.
그러나 설계나 코드가 있다는 이유만으로 위 항목을 검증 완료로 표시하지 않습니다.
장비·권한·실험 범위의 한계를 보완한 뒤 실제 실행 결과를 추가해야 합니다.

## 현재 코드와 과거 기록의 구분

이 보고서와 원본 JSON은 당시 2조건·30회 실험의 기록을 유지합니다.
현재 collectionbench CLI는 무계산 2왕복 대조군을 포함한 3조건·45회를 실행합니다.
새 결과와 미검증 항목의 최신 상태는 [대조 실험 보고서](CONTROLBENCH-REPORT.md)와
[README](../README.md#미검증-항목과-이유)를 확인하세요.

## 재현 및 검증

```bash
python -m unittest discover -s tests -v
# 아래 명령은 현재 버전에서 3조건 대조 실험을 실행합니다.
python -m arta.collectionbench --seconds 5 --repeats 5 --workers 1 2 4 --resources 100000
```

기능 테스트 27개 통과. 테스트 수는 보안 공격 차단 수가 아니다.
원본 결과: [collectionbench-results.json](collectionbench-results.json).
기존 [2초 반복 조회 보고서](TOLLBENCH-REPORT.md)는 과거 실험 기록으로 유지한다.

다음 검증은 동일 왕복의 무계산 대조군, 전용 환경 장기 반복, 서버 동시 처리 비교,
격리가 검증된 환경에서의 실제 AI 실험이다. 이 보고서는 해당 작업의 완료를 주장하지 않는다.
