# Healing Arty & Arta 공동개발 — 추가 아이디어 검토·개발 보고서

2026-10-07。ARTA MATRYOSHKA ローカル実験版。公開防御製品ではない。

## 결론

연결된 단서와 일관된 가짜 상태를 기본으로 하며, 여러 문·쉬운 힌트·거울·가짜 출구는
옵션으로 비교한다. AI가 똑똑할수록 검증 비용이 증가한다는 가설은 아직 미검증이다.
기능을 만들 수 있다는 것과 공격자를 지연시킨다는 것은 별개다.

## 1. 기존 기술과 겹치는 부분

가짜 시스템, 미끼 자격정보, 유인용 단서와 상대 행동 관측은 기존 기만·적대자 관여 분야에 속한다.
MITRE Engage는 이런 활동의 계획 체계를 제공한다. 따라서 여러 방과 단서를 새 발명으로 주장하지 않는다.

- https://www.mitre.org/news-insights/news-release/mitre-launches-engage-framework-defend-against-cyber-attacks
- https://engage.mitre.org/wp-content/uploads/2022/04/EngageHandbook-v1.0.pdf
- https://www.mitre.org/news-insights/impact-story/active-defense-using-deception-and-trickery-defeat-cyber-adversaries

## 2. 실제로 새로운 부분에 대한 판단

검토 범위에서 프로젝트의 새 연구 방향은 AI 에이전트의 검증 행동을 독립 변수로 삼고,
쉬운 단서·분기 수·반영된 상태·가짜 출구에 대한 반응을 계측하는 것이다.
세계 최초나 기존 연구에 없다는 주장은 하지 않는다. 체계적인 선행연구 검토와 실제 실험이 필요하다.

## 3. 효과가 없거나 역효과일 위험

| 아이디어 | 실패 가능성 |
|---|---|
| 쉬운 문제 | AI가 그냥 이용해 탐색을 더 빨리 완료할 수 있다 |
| 착시형 구조 | 모순으로 보이면 미끼 발견을 앞당긴다 |
| 거울방 | 복제/캐시로 설명하고 추가 검증을 생략할 수 있다 |
| Many Doors | 낮은 가치의 문을 무시하거나 병렬화할 수 있다 |
| False Exit | 동일한 URL·응답 패턴으로 같은 서비스임을 발견할 수 있다 |
| 깊이·경로 불확실성 | AI가 실제 목표와 무관하다고 판단하고 즉시 떠날 수 있다 |

현재 거울 응답은 source를 명시하므로 복제 조회 기준선이다. 자기 흔적 혼동을 일으키는
정교한 연출이 아니다. manifest도 동일 사실의 요약/세부 표현일 뿐 의미적 착시의 구현은 아니다.

## 4. 실험 가치와 현재 구현

| 아이디어 | 이번 구현 | 효과 검증 |
|---|---|---|
| 연결된 단서 | 백업 코드 → 복구 → 작업 공간 → 다음 시스템 | 기능만 검증 |
| False Exit | 최대 3회, 로컬 경로, 별도의 가짜 설정 상태 | 실제 탈출 착각 미검증 |
| Many Doors | 0..8개의 유한 문, 기존 로컬 방으로 합류 | AI 선택 우선순위 미검증 |
| 쉬운 문제 | 관리자 응답에 복구 코드 제공하는 easy 옵션 | 의심/추론 증가 미검증 |
| 거울방 | 현재 설정 boolean·revision만 반영 | 에이전트 혼동 미검증 |
| 착시형 구조 | manifest 요약·상세 일관성 기준선 | 분석 깊이 효과 미구현 |
| 문 자체 의심 | 미지 경로를 안전하게 404 처리하고 예산 소비 | 문 외 탐색 이유는 관측 불가 |

어떤 단서도 실제 서버 주소·실제 자격정보가 아니다. 외부 리다이렉트, URL 가져오기,
셸 실행, 상대 장치 코드 실행은 추가하지 않았다. 새 옵션은 기본 baseline에서 꺼져 있다.

## 5. 먼저 필요한 안전장치

### 이번에 추가

- 세계 요청 예산에 미지 경로/실패 요청도 포함.
- 세계 문 수 최대 8, False Exit 최대 3, 세션 예산 100회.
- 실행시간 기본 900초, 최대 3600초에서 자동 종료.
- SQLite DB 본체 페이지 예산 16 MiB, 실패 시 롤백·저장 오류 표시.
- 수집기 입력 처리 초당 100개 초과 시 폐기 카운터 증가.
- 새로운 이벤트 경로·상태 전이를 수집기의 유한 스키마로 검증.
- 실제 HTTP 흐름에서 코드 비밀값 미기록 확인.

DB 페이지 제한은 journal·모든 OS 임시 파일의 총 용량 상한이 아니다.
수집기 rate limit은 UDP 네트워크/커널 비용까지 제한하지 않는다. 악의적 로컬 송신자가
기록을 밀어낼 수 있다. 폐기된 기록은 복구하지 않는다.

### 여전히 미완성

같은 OS 계정의 두 프로세스는 강력한 격리가 아니다. 미끼 장악 시 계정 접근 가능한
파일·관측 토큰·네트워크가 위험하다. 별도 OS 권한 또는 호스트, 실제 관리망 차단,
독립 기록 저장·유실 탐지, 전체 요청 기한과 제한된 동시처리가 우선 과제다.
강력한 격리를 검증하기 전에는 인터넷 노출·실제 자산 연결을 하지 않는다.

## 테스트 결과

로컬 unittest 20개 통과. 기존 11개 외에 다음 검증을 추가했다.

- 설정 옵션의 타입/상한, 기본 비활성화.
- 문 경로의 로컬 상대 경로·유한 개수.
- False Exit 사전 접근 거부, 단계 건너뛰기 거부, GET 무변경, 반복 POST의 멱등성.
- 각 가짜 작업 공간의 설정 분리와 최종 출구 제한.
- 거울/manifest revision 일관성과 임의 입력 반영 거부.
- 미지 경로도 세계 예산 소비.
- SQLite page 예산 도달 시 안전한 실패·기록 연결 유지.
- HTTP 통합 흐름과 새로운 기록 스키마, 복구 코드 미기록.
- 실행시간 예산 도달 시 정상 종료.

## 고정 스크립트 비교

`python -m arta.experiment`로 6가지 환경 × 3가지 고정 스크립트 = 18회 실행했다.
AI, 추론 토큰, 외부 공격, 네트워크 체류 시간, 자원 비용은 측정하지 않았다.
이 숫자는 코드가 정한 경로를 따라간 기능 비교이지 기만 효과의 증거가 아니다.

| 환경 | direct 요청 | verify 요청 | enumerate 요청 |
|---|---:|---:|---:|
| baseline | 6 | 10 | 8 |
| linked | 8 | 14 | 10 |
| many-doors | 8 | 14 | 16 |
| mirror | 8 | 15 | 10 |
| easy | 5 | 9 | 7 |
| combined | 9 | 17 | 17 |

모두 가짜 목표 설정 변경에 성공했고, 실제 목표는 존재하지 않는다.
Many Doors는 enumerate 스크립트의 요청 수를 늘렸지만 direct/verify는 문을 무시했다.
easy는 고정 스크립트의 요청 수를 줄였다. 따라서 '쉬운 단서가 의심을 늘린다'는 가설은
별도 AI 실험 없이는 주장할 수 없다. combined는 여러 변수를 함께 바꾸므로
각 옵션의 인과 효과를 분리할 수 없다. 설정을 하나씩 바꾸는 후속 비교가 필요하다.

원본 추적: [scripted-results.json](scripted-results.json).
재조회 수는 반복 GET 수일 뿐 AI 재검증 횟수로 해석하지 않는다.

## 다음 실험

허가된 격리 환경에서 모델·도구·시간·요청 예산과 과제를 고정한다.
한 번에 한 변수를 바꾸고 반복 실행해 성공/실패/포기까지 전부 기록한다.
미끼 탐지·탈출·성공 판단은 에이전트의 명시적 보고와 독립된 상태 확인으로 판정한다.
요청만 보고 AI의 의심을 추정하지 않는다. 추론/도구 비용은 클라이언트에서 계측한다.
이탈 후 실제 자산 방향의 행동은 독립적인 관측 환경과 안전한 차단 경계가 있어야 측정할 수 있다.

## 자체 문답

Q: 문이 많으면 비용이 늘어나는가?
A: 모든 문을 조사하는 스크립트에서만 증가했다. 일반 AI로 확장할 수 없다.

Q: False Exit가 실제 자산으로 연결되는가?
A: 응답은 허용된 로컬 경로와 메모리 상태만 사용한다. 다만 프로세스 침해 시 네트워크
접근까지 OS가 막는 것은 아니므로 '완전 격리'라고 주장하지 않는다.

Q: 거울에 공격자의 문자열을 그대로 넣는가?
A: 아니다. 허용한 boolean과 revision만 반영한다. 추후 AI 관제가 읽어도 공격자 입력이
명령처럼 전달되는 경로를 줄이기 위한 선택이다.

Q: 새로운 기능을 전부 켜는 것이 좋은가?
A: 아니다. 기본 baseline을 유지하고 개별 비교에서 효과를 확인해야 한다.

Q: AI의 높은 지능을 실제로 비용으로 바꿨는가?
A: 아직 아니다. 그 가설을 검증할 옵션과 기능 테스트 기반을 만든 단계다.
