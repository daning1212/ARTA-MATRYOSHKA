# 설계와 AI 평가 계획

## 핵심 가설

AI의 재검증 능력을 역이용한다. 여러 조회와 변경 결과가 일관된 가짜 상태를 가리키면
에이전트가 탐색·검증을 이어갈 수 있는지 측정한다. 더 똑똑한 AI가 반드시 더 오래 머문다는
주장은 하지 않는다. 미끼 발견, 조기 포기, 다른 표적 전환도 결과로 기록한다.

## 유한 세계

방 일곱 경로: 입구, 관리자, 백업, 진단, 복구, 작업 공간, 설정.
관리자와 백업 경로는 복구와 설정에서 다시 합쳐진다. 세계 상태는 sandbox 또는 workspace.
복구는 실제 탈출이 아닌 가짜 상태 전이이다. 권한 거부와 성공은 상태에 따라 결정되며
무작위로 섞지 않는다. 세션 15분·100회 예산, 최대 1,000세션으로 제한한다.

## 기록 경계

미끼 프로세스 → 크기가 제한된 JSON UDP → 수집기 프로세스 → SQLite.
수집기는 별도 관측 토큰으로 조회를 인증한다. 미끼에 전달되는 기록 토큰은 조회에 사용할 수 없다.
UDP 수집 주소는 loopback 고정이며 미끼가 보내는 항목을 스키마 검증한다.
프로세스 큐의 pickle 역직렬화는 기록 경계에서 사용하지 않는다.

같은 OS 사용자의 권한과 네트워크 접근은 공유된다. 따라서 이것은 로컬 실험 구조이며,
실제 침해를 견디는 격리 구조가 아니다. 실제 운영에는 별도 호스트/OS 계정/샌드박스,
독립 수집기, 네트워크 정책, 비밀 관리, 불변 기록과 부하 검증이 필요하다.

## 평가 순서

1. 단순 미끼 기준선.
2. 일관된 분기·가짜 복구를 갖춘 미끼.
3. 별도의 가벼운 계산 통행료.
4. 분기와 계산 통행료 결합.

통제한 소유 환경에서 여러 에이전트·반복 실행으로 비교한다.
실험 시간·요청·계산 예산을 제한하고 중단 조건을 먼저 정한다.
AI의 자체 성공 보고와 평가자가 별도 경로에서 확인한 실제 상태를 비교한다.

측정: 체류 시간, 발견 시간, 거짓 탈출·성공 보고율, 요청 수, 중도 포기와 경로 전환,
실제 보호 대상의 피해 여부, 공격자와 방어자의 CPU/메모리/비용.
서버 요청만으로 AI의 추론 토큰이나 상대 CPU 사용량을 알 수 없다. 그런 값은
통제 실험의 클라이언트 계측에서만 얻고, 관측된 값과 추정을 구분한다.

## 계산 통행료는 후속 실험

일반 PoW는 병렬화 가능하다. 단계 의존성은 다음 단계의 사전 실행을 제한하지만
단계 안의 계산과 여러 세션의 병렬화를 막지 못한다. 순차 계산을 연구할 때는
검토된 VDF 구현과 가정을 조사하고 자체 암호 설계를 피한다.
정상 사용자에게 무거운 계산을 강제하거나 상대 기기를 손상시키지 않는다.
