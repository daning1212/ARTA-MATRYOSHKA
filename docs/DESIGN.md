# 설계와 평가 계획

## 목표

격리된 미끼 상태를 일관되게 보여주어 공격 에이전트가 가짜 성공을 보고하는지 측정한다.
정상 사용자의 인증과 실제 서버 방어를 대체하지 않는다.

## 현재 구조

로컬 클라이언트 → 미끼 HTTP 포트 → 세션별 메모리 상태.
접근 이벤트 → SQLite 기록 → 별도 로컬 관측 포트.
실제 서버로의 연결, 쉘 실행, 파일 업로드 실행, 임의 외부 요청 기능은 없다.
이것은 기능적 분리이며 OS 수준의 샌드박스는 아니다.

## 운영 격리 구현 전 필수 조건

- 미끼를 별도 호스트 또는 검증된 샌드박스에서 실행하고 실제 서버·관리망 접근 차단.
- 미끼의 임의 외부 통신 차단. 기록 전달만 제한된 경로로 허용.
- 별도 신뢰 영역의 인증된 기록 수집기와 변조 방지·보관 정책.
- 자원 제한, 연결 제한, 장애 시 복구 절차와 부하 검증.
- 관제 인증, 실제 서비스의 독립 인증 및 인가.

## AI 실험

소유한 격리 테스트 환경에서만 수행한다. 실제 공격 도구는 이 저장소에 포함하지 않는다.
에이전트에 가상 설정 변경 과제를 주고, 사전에 정한 시간·요청 예산 안에서 실행한다.
미끼 없는 기준 환경과 미끼 환경을 비교한다. 가짜 표식과 실제 환경 상태는 평가자가
별도 신뢰 경로로 확인한다. 여러 모델·반복 실행을 사용하고 실패 사례도 공개한다.

측정: 거짓 성공 보고율, 미끼 발견률, 탐색 시간, 요청량, 방어 측 자원 사용량.
현재는 어떠한 AI 기만 성공률도 주장하지 않는다.

## 향후 모듈

웹/API 어댑터, 외부 로그 수집기, 알림, 인증된 관제, 중요한 관리 작업의 두 사람 승인.
공유기 및 무선 보안은 별도 장비·권한·관측 범위를 정의한 뒤 별도 모듈로 검토한다.
AI 기반 판정은 규칙 기반 기준선과 비교한 후 도입한다.
