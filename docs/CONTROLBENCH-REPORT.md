# 무계산 2왕복 대조 실험

2026-10-07. Healing Arty & Arta 공동개발.

## 결론

1프로세스의 같은 2왕복 비교에서 no-work 대비 pow의 고유 수집량 감소율은
반복별 비율 평균 95.41% ± 표본 표준편차 0.76퍼센트포인트였다.
자료당 예산 추정에서 추가 솔버 작업의 차이는 16.4438ms/건이었다.
왕복 비용만으로 전체 차이를 설명할 수 없지만, 이는 이 구현의 추가 계산 부담을
관측한 결과이며 공격 차단·미끼 기만·실제 자료 보호 성과를 입증하지 않는다.
특히 2프로세스 no-work 수집량의 표준편차가 평균의 약 61%로 커서 정밀한
효과 크기 추정이나 하드웨어 일반화에 사용하지 않는다.

## 목적과 조건

기존 결과에 포함된 HTTP·프로토콜 비용과 PoW 추가 비용을 구분하기 위해
같은 서버·합성 자료·시간 예산에서 아래 세 조건을 비교했다.

| 조건 | 자료당 HTTP 왕복 | 클라이언트 작업 | 서버 동작 |
|---|---:|---|---|
| direct | 1 | record 직접 조회 | 퍼즐 검사 생략 |
| no-work | 2 | challenge 조회 → nonce=0으로 record 조회. 해시 탐색 0회 | 자료 ID·만료·일회성 검사, SHA-256 1회 |
| pow | 2 | challenge 조회 → 14비트 해시 탐색 → record 조회 | no-work와 같은 검증 경로, SHA-256 1회 |

무계산은 **클라이언트의 퍼즐 해시 탐색이 없다**는 뜻이다. HTTP·JSON·토큰 관리·서버 검증까지
무료라는 뜻이 아니다. challenge 토큰은 세션에 연결되지 않는 기존 bearer 방식 그대로다.

- 자료 100,000개. 동일 크기 payload의 서로 다른 ID를 분할하여 한 번씩 조회.
- 클라이언트 CPU 프로세스 1·2·4개, 조건별 5초 × 5회: 총 45회, 측정 예산 225초.
- 모든 프로세스가 준비된 뒤 공통 deadline 시작. 시작·종료 시간은 측정 예산 외.
- 반복별 프로세스 수·조건 순서를 회전하고 홀수 반복에는 조건 순서를 반전.
- 이 측정에는 기능 테스트를 병행하지 않았다. 전용 머신이나 호스트의 다른 부하까지 통제한 것은 아니다.
- 환경: Python 3.12.14, Linux-6.18.44-x86_64-with-glibc2.39, 표시된 논리 CPU 9개.
- localhost 단일 동기식 HTTP 서버. 네트워크 지연·GPU·실제 AI·OS 격리를 새로 검증하지 않았다.

확인한 자료에 자동 합산하지 않는다.

## 왕복을 맞춘 비교

같은 프로세스 수·반복 ID에서 D=direct, C=no-work, P=pow의 고유 수집량으로 비교했다.
아래 감소율은 paired 실행의 비율을 구한 뒤 평균 ± 표본 표준편차를 계산했다.

| 프로세스 | direct→no-work 감소율: 1−C/D | no-work→pow 추가 감소율: 1−P/C | direct→pow 총 감소율: 1−P/D |
|---:|---:|---:|---:|
| 1 | 46.22% ± 10.01퍼센트포인트 | 95.41% ± 0.76퍼센트포인트 | 97.54% ± 0.55퍼센트포인트 |
| 2 | 62.29% ± 17.13퍼센트포인트 | 94.07% ± 4.82퍼센트포인트 | 98.22% ± 0.84퍼센트포인트 |
| 4 | 50.17% ± 8.63퍼센트포인트 | 94.79% ± 1.40퍼센트포인트 | 97.48% ± 0.38퍼센트포인트 |

direct→no-work는 추가 HTTP 왕복과 challenge 생성·토큰 관리·검증 등 프로토콜 비용을
함께 반영한다. no-work→pow는 왕복 수를 맞춘 상태에서 **해시 탐색·Python 루프·deadline
확인·해시 결과 검사 등 이 솔버의 추가 작업**이 있을 때의 차이다. 순수 SHA-256 연산만의 비용은 아니다.
세 감소율의 분모가 다르므로 앞의 두 감소율을 단순히 더하면 총 감소율이 되지 않는다.

## 1프로세스에서의 자료당 비용 추정

직렬 클라이언트 조건에서 각 실행의 시간 예산/확인 자료 수와 CPU초/확인 자료 수를
계산하고 평균했다. 완료되지 않은 마지막 작업의 비용도 포함하는 예산 기준 추정이다.
개별 요청 지연 분포를 계측한 값은 아니며 여러 프로세스에는 이 직렬 해석을 적용하지 않는다.

| 조건 | 예산/확인 자료: ms/건 | 클라이언트 CPU: ms/건 | 서버 CPU: ms/건 |
|---|---:|---:|---:|
| direct | 0.4260 | 0.2133 | 0.1976 |
| no-work | 0.7952 | 0.4293 | 0.4135 |
| pow | 17.2390 | 16.4997 | 0.7481 |

자료당 예산 추정의 direct→no-work 차이는 0.3692ms/건, no-work→pow 차이는 16.4438ms/건이다.
전체 차이 16.8130ms/건 중 후자의 산술 비율은 97.80%다.
이는 **이번 1프로세스 구현의 자료당 예산 차이를 산술 분해한 추정**이다.
과거 2초·스레드 실험의 “약 98% 감소” 중 해시의 비율로 소급 적용할 수 없고,
순수 해시·GPU 비용·실제 공격 방어 효과의 비율도 아니다.

## 해결한 것과 남은 것

| 항목 | 상태와 이유 |
|---|---|
| 같은 왕복 수의 무계산 대조군 | 구현·45회 비교 측정 완료. 2왕복 기준선에서도 추가 솔버 작업의 차이를 관측 가능 |
| 퍼즐의 세션 바인딩 | 구현하지 않음. 자료 ID·만료·일회성만 연결하며 토큰 전달·공유 가능. 이번 실험으로 해결됐다고 주장하지 않음 |
| 단순 rate limit·일반 PoW·기존 허니팟과 전체 방식 비교 | 미실시. 이번 모듈 자체가 일반 해시 PoW이며 세 조건은 프로토콜/계산 비용 대조군. 기존 방식 대비 우수성을 검증한 비교군이 아님 |
| 실제 AI·GPU·분산 계산·강력한 OS 격리 | 기존 미검증 상태 유지. 해당 환경과 검증 결과를 흉내 내거나 새 성과로 표시하지 않음 |
| 장기·운영 효과 | 5초 × 5회·동일 호스트·고정 스크립트·단일 서버이므로 미검증. PoW의 무작위 탐색 편차와 호스트 자원 변화가 있음 |

위협 모델의 실제 자산은 연구에서 상정하는 대상일 뿐 현재 앱이 연결·보호하는 대상이 아니다.
